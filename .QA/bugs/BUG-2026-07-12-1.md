# BUG-2026-07-12-1: Cadastro de cliente salva no banco mas não exibe feedback de sucesso na UI

## Informações Gerais

- **Data:** 2026-07-12
- **Severidade:** MÉDIA
- **Componente:** `RegistrationComponent` (Clientes)
- **Rota:** `/customer/registration`
- **Autor:** QA Automatizado (Cascade)

## Descrição

Ao cadastrar um cliente válido no formulário de "Cadastro de Cliente", o registro é persistido no banco de dados, porém a interface não apresenta nenhum feedback de sucesso. O formulário mantém os dados preenchidos, o campo "Código" continua vazio e o botão "Excluir" permanece desabilitado, dando a impressão de que a operação não foi concluída.

## Passos para Reproduzir

1. Fazer login como `admin` (`admin` / `Cocob0st@12`)
2. Acessar **Clientes → Cadastro de Cliente** (`/customer/registration`)
3. Preencher os campos obrigatórios:
   - Nome Completo: `Cliente Teste QA`
   - Documento: `111.444.777-35` (CPF válido)
   - E-mail: `qa@teste.com`
   - Endereço completo (CEP, logradouro, bairro, cidade, UF, número)
   - Telefone: `11999999999`
4. Clicar em **Salvar**

## Comportamento Esperado

- Exibir uma mensagem/toast de sucesso (ex: "Cliente cadastrado com sucesso")
- Limpar o formulário ou carregar o cliente recém-criado em modo de edição
- Preencher o campo "Código" (legacyId) e habilitar o botão "Excluir"

## Comportamento Atual

- Nenhum toast, snackbar ou mensagem de sucesso é exibido
- O formulário continua preenchido com os dados informados
- O campo "Código" permanece vazio
- O botão "Excluir" continua desabilitado
- O registro é criado no banco (verificável via query)

### Query de Validação

```sql
SELECT p.id, p.name, p.document, p.email, p.created_at
FROM people p
JOIN customers c ON c.id = p.id
WHERE p.document = '11144477735'
ORDER BY p.created_at DESC;
```

### Logs de Erro

Nenhum erro visível no console do navegador.

## Contexto Técnico

- **Ambiente:** local
- **Browser:** Puppeteer (Chromium)
- **Backend:** Spring Boot 3.4.1 / Java 21 — localhost:8080
- **Frontend:** Angular 21 — localhost:4200
- **Banco:** PostgreSQL (`rentafit`)

## Impacto

Usuário não tem certeza se o cadastro foi realizado, podendo clicar em Salvar novamente e criar duplicatas (o backend possui unique em documento/e-mail, então gera erros de duplicidade na segunda tentativa). A experiência é confusa e prejudica a operação diária.

## Workaround

Verificar manualmente no banco de dados se o cliente foi criado, ou navegar para outra tela e retornar para conferir.

## Correção Sugerida

No `RegistrationComponent`, após a resposta bem-sucedida do `service.save()`:

1. Exibir mensagem de sucesso via `showSuccess()` ou serviço de toast
2. Atualizar o estado do componente (`customer` / `customerData`) com o cliente retornado
3. Preencher o `legacyId` no formulário
4. Habilitar o botão "Excluir" quando houver `id`/`legacyId`

**CORRIGIDO em 2026-07-19** na branch `fix/bug-1-customer-save-feedback` (commit `67fcb66`). Revalidado com criação de cliente: resposta `201`, mensagem de sucesso, `id`/`legacyId` carregados e formulário em modo somente leitura.
