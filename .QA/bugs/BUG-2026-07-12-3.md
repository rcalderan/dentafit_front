# BUG-2026-07-12-3: Identificação de atendente com iniciais inválidas gera erro JS "Cannot read properties of undefined (reading 'logs')"

## Informações Gerais

- **Data:** 2026-07-12
- **Severidade:** ALTA
- **Componente:** `NewRentalComponent` / `EmployeeVerifyComponent`
- **Rota:** `/rental/new`
- **Autor:** QA Automatizado (Cascade)

## Descrição

Na tela de nova locação, ao clicar em **Adicionar Item** e informar iniciais de funcionário que não existem no cadastro (ex: `QA`), o modal "Identificar Atendente" exibe o erro JavaScript `Cannot read properties of undefined (reading 'logs')` em vez de uma mensagem amigável como "Funcionário não encontrado".

## Passos para Reproduzir

1. Fazer login como `admin`
2. Acessar **Locações → Novo Contrato** (`/rental/new`)
3. Buscar e selecionar um cliente (ex: `111.444.777-35`)
4. Clicar em **Adicionar Item**
5. No modal "Identificar Atendente", digitar iniciais inexistentes: `QA`
6. Clicar em **Confirmar**

## Comportamento Esperado

- O sistema deve informar que o funcionário não foi encontrado
- Exibir mensagem clara: "Iniciais não cadastradas" ou similar
- Não exibir erro técnico de JavaScript

## Comportamento Atual

- O modal exibe: `Cannot read properties of undefined (reading 'logs')`
- O usuário fica bloqueado na ação sem saber o motivo

## Evidências

### Screenshots

- `locacao-attendant-error.png` — modal com a mensagem de erro JS

### Logs de Erro

```
Cannot read properties of undefined (reading 'logs')
```

### Query de Validação

```sql
-- Funcionário ADM existe, QA não existe
SELECT e.initials, p.name
FROM employees e
JOIN people p ON p.id = e.id
WHERE e.initials IN ('ADM', 'QA');
-- Retorna apenas ADM
```

## Contexto Técnico

- **Ambiente:** local
- **Browser:** Puppeteer (Chromium)
- **Backend:** Spring Boot 3.4.1 / Java 21 — localhost:8080
- **Frontend:** Angular 21 — localhost:4200
- **Banco:** PostgreSQL (`rentafit`)

## Impacto

**BLOQUEADOR PARCIAL** — Impede a adição de itens quando o funcionário não é reconhecido. O erro técnico exposto gera má experiência e dificulta o diagnóstico operacional.

## Workaround

Utilizar iniciais de funcionário cadastrado (ex: `ADM`).

## Correção Sugerida

1. No componente de verificação de funcionário, tratar o cenário de funcionário não encontrado
2. Exibir mensagem amigável ao invés de propagar erro de leitura de `logs`
3. Garantir que o error handler não acesse propriedades de objeto indefinido

## Status da Correção

**CORRIGIDO em 2026-07-19** na branch `fix/bug-3-attendant-invalid-initials`. O componente trata erros como `unknown` e exibe mensagem operacional para funcionário não encontrado, sem acessar propriedades indefinidas.
