# BUG-2026-05-10-7: Busca de item por código legado no modal "Adicionar Item" causa erro JS e logout indevido

## Informações Gerais

- **Data:** 2026-05-10
- **Severidade:** ALTA
- **Componente:** `NewRentalComponent` / `AuthInterceptor`
- **Rota:** `/rental/new`
- **Autor:** QA Automatizado (Cascade)

## Descrição

Ao tentar adicionar um item de locação no modal "Adicionar Item" usando um código legado válido (ex: `011`), o sistema exibe o erro `Cannot read properties of undefined (reading 'logs')` e o interceptor realiza logout automático indevido, redirecionando para `/`.

O problema tem **duas causas raiz encadeadas**:

1. O endpoint `GET /api/v1/products/rental/byLegacy/{legacyId}` retorna **403** quando chamado pelo Angular (mas 200 com token manual via fetch) — indicando que o interceptor consome ou invalida o token antes da requisição chegar ao backend em determinado estado.
2. O `AuthInterceptor` trata **403** da mesma forma que **401** (tenta refresh automático). Ao falhar o refresh, chama `logout()` e redireciona para `/auth/login`. Porém a URL final é `/` (não `/auth/login`), sugerindo que o guard ou location strategy captura e redireciona antes.
3. O componente `searchItemByCode()` tipifica o `error` callback como `Error`, mas recebe `HttpErrorResponse` (ou o erro de refresh). Quando acessa `err.message`, o objeto é um `HttpErrorResponse` com `error.error` vazio → crash `Cannot read properties of undefined (reading 'logs')`.

## Passos para Reproduzir

1. Fazer login como `admin`
2. Criar uma locação (`/rental/new`)
3. Buscar cliente pelo CPF
4. Clicar em "Adicionar Item"
5. Identificar atendente (iniciais: ADM, PIN: 1234)
6. No modal "Adicionar Item", digitar o código legado `011` no campo "Código do Produto"
7. Clicar no botão 🔍

## Comportamento Esperado

O produto "Vestido de Noiva Clássico Renda" (legacy_id: 011, status: AVAILABLE) deve ser carregado no modal com nome, tamanho e valor.

## Comportamento Atual

1. Modal exibe: `Cannot read properties of undefined (reading 'logs')`
2. Em seguida, o interceptor faz logout e redireciona para `/`
3. O fluxo de locação é completamente interrompido

### Trecho de código com o problema

**`auth.interceptor.ts` linha 33** — 403 tratado como 401:
```typescript
if ((error.status === 401 || error.status === 403) && !req.url.includes('/auth/refresh')) {
  return authService.refreshToken().pipe(  // ← 403 NÃO deve tentar refresh
```

**`new-rental.component.ts` linha 488** — tipo errado no error callback:
```typescript
error: (err: Error) => {  // ← HttpErrorResponse chega aqui, não Error
  this.itemModalError = err.message || 'Produto não encontrado.';
  // err.message em HttpErrorResponse acessa error.error.logs em algum ponto → crash
}
```

**Hipótese adicional**: O JWT não contém claims de roles (`authorities`/`roles`) — o backend pode estar falhando na autorização do endpoint `byLegacy` por ausência de role no token, retornando 403.

## Impacto

**BLOQUEADOR** — Impede completamente a adição de itens em um contrato de locação. O fluxo principal do sistema (nova locação) fica inutilizável.

## Workaround

Nenhum workaround disponível via UI. Contornar via API direta:
```bash
curl -H "Authorization: Bearer <token>" http://localhost:8080/api/v1/products/rental/byLegacy/011
```

## Correções Sugeridas

### Fix 1 — `auth.interceptor.ts`: separar tratamento de 401 e 403
```typescript
// 401 = token expirado → refresh
// 403 = sem permissão → NÃO fazer refresh, apenas propagar erro
if (error.status === 401 && !req.url.includes('/auth/refresh')) {
  return authService.refreshToken().pipe(...)
}
return throwError(() => error);
```

### Fix 2 — `new-rental.component.ts`: tipar corretamente o error callback
```typescript
error: (err: HttpErrorResponse) => {
  this.itemModalError = err.error?.message || err.message || 'Produto não encontrado.';
}
```

### Fix 3 — Backend: verificar geração do JWT e autorização do endpoint `byLegacy`
- Verificar se o claim `roles`/`authorities` está sendo incluído no JWT
- Verificar `SecurityConfig` se o endpoint `/api/v1/products/rental/byLegacy/**` exige role específica

## Status da Correção

**CORRIGIDO em 2026-07-19** na branch `fix/bug-4-auth-403-logout` (commit `be073e4`). O interceptor agora renova token apenas para `401`; uma resposta `403` é propagada sem logout. Revalidado no navegador com resposta `403`: a sessão foi preservada.
