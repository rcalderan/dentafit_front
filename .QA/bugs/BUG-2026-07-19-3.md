# BUG-2026-07-19-3: Filtro de vendas canceladas retorna erro interno

## Informações Gerais

- **Data:** 2026-07-19
- **Severidade:** MÉDIA
- **Componente:** `SalesOrderController` / `SalesOrderRepository`
- **Endpoint/Rota:** `GET /api/v1/sales/orders?status=CANCELLED`
- **Autor:** Cascade QA

## Descrição

A listagem de vendas falha com HTTP 500 ao aplicar o filtro de status `CANCELLED`. O operador não consegue consultar pedidos cancelados pela tela de gestão de vendas.

## Passos para Reproduzir

1. Autenticar como administrador.
2. Abrir `/sales/management`.
3. Selecionar o filtro `Cancelado`.

## Comportamento Esperado

A API deve retornar `200` com uma página vazia ou com os pedidos de venda cancelados.

## Comportamento Atual

A requisição retorna `500` e a interface exibe `Erro interno no servidor. Tente novamente mais tarde.`

## Evidências

### Backend

```bash
curl -H "Authorization: Bearer <access-token>" \
  "http://localhost:8080/api/v1/sales/orders?page=0&size=20&sort=createdAt,desc&status=CANCELLED"
```

### Logs de Erro

```text
GET /api/v1/sales/orders?page=0&size=20&sort=createdAt,desc&status=CANCELLED
HTTP 500
```

### Screenshots (Frontend)

A tela `/sales/management` apresentou a mensagem `Erro interno no servidor. Tente novamente mais tarde.` após o filtro `Cancelado`.

### Query de Validação (se aplicável)

```sql
SELECT id, legacy_id, status, created_at
FROM sales_orders
WHERE status = 'CANCELLED'
ORDER BY created_at DESC;
```

## Contexto Técnico

- **Ambiente:** local
- **Browser:** Chromium via Puppeteer
- **Backend:** Spring Boot 3.4.1 / Java 21
- **Frontend:** Angular 21
- **Banco:** PostgreSQL local

## Impacto

A funcionalidade de filtrar vendas canceladas fica indisponível; não há alternativa equivalente na interface.

## Workaround

Consultar todas as vendas e identificar visualmente o status ou consultar o banco de dados.

## Status da Correção

**CORRIGIDO em 2026-07-19** na branch backend `fix/bug-5-sales-cancelled-filter` (commit `2d04cd5`). O filtro exclusivo de status agora usa a consulta derivada por status. O teste de regressão passou com 14 testes e zero falhas.
