# BUG-2026-07-12-2: Cadastro de produto de aluguel falha silenciosamente quando categoria não é vinculada por ID

## Informações Gerais

- **Data:** 2026-07-12
- **Severidade:** ALTA
- **Componente:** `RegistrationComponent` (Produtos / Aluguel)
- **Rota:** `/product/registration`
- **Autor:** QA Automatizado (Cascade)

## Descrição

No cadastro de produto para aluguel, o campo "Categoria" aceita texto livre e abre um modal de gerenciamento de categorias, mas não vincula o `categoryId` ao produto. O formulário fica válido mesmo com `categoryId` vazio, o clique em **Salvar Produto** não gera mensagem de erro e o produto não é persistido no banco.

## Passos para Reproduzir

1. Fazer login como `admin`
2. Acessar **Produtos → Cadastro Aluguel** (`/product/registration`)
3. Preencher os campos obrigatórios:
   - Categoria: digitar `Vestido de Noiva` (texto livre) ou selecionar via modal
   - Valor Aluguel: `150`
   - Nome do Produto: `Vestido Teste QA`
   - Tamanho: `M`
   - Marca: `Marca QA`
   - Cor Principal: `Branco`
   - Condição: `Novo`
4. Clicar em **Salvar Produto**

## Comportamento Esperado

- O sistema deve vincular um `categoryId` válido (UUID) ao produto
- Se a categoria não for encontrada/vinculada, o formulário deve ser inválido e exibir mensagem de erro
- Ao salvar, o produto deve aparecer no banco de dados

## Comportamento Atual

- O campo `categoryId` do formulário Angular permanece vazio (`""`)
- O modal "Gerenciar Categorias" permite selecionar uma categoria, mas não popula `categoryId`
- O botão **Salvar Produto** é acionado sem erro aparente
- Nenhum toast de sucesso ou erro é exibido
- O produto **não é criado** no banco de dados

## Impacto

**BLOQUEADOR** — Impede o cadastro de novos produtos de aluguel pela interface. O usuário não recebe nenhum indicativo de falha, gerando perda de tempo e dados aparentemente perdidos.

## Workaround

Somente via API direta informando um `categoryId` válido (UUID), conforme testado em ambiente QA.

## Correção Sugerida

1. Transformar o campo Categoria em uma seleção obrigatória que popule `categoryId`
2. Tornar `categoryId` required no formulário Angular
3. Exibir erro claro quando o backend retornar falta de categoria
4. Exibir toast de sucesso/erro após a chamada de salvamento
