# BUG-2026-07-19-1: Cadastro de cliente válido é rejeitado sem feedback

## Informações Gerais

- **Data:** 2026-07-19
- **Severidade:** ALTA
- **Componente:** Angular `RegistrationComponent` / API de clientes
- **Endpoint/Rota:** `POST /api/v1/customers` via `/customer/registration`
- **Autor:** Cascade QA

## Descrição

O formulário de cadastro de clientes aceitou todos os campos obrigatórios como válidos, mas a tentativa de salvar retornou HTTP 422. Nenhuma mensagem de erro ou modal foi mostrada ao usuário, que permanece no formulário preenchido sem saber que o cadastro falhou.

## Passos para Reproduzir

1. Autenticar no ambiente local com um usuário administrador.
2. Abrir `/customer/registration`.
3. Informar nome `QA Cliente 20260719`, CPF `52998224725`, e-mail válido, endereço completo e telefone `(16) 99999-9999`.
4. Confirmar que o formulário está com status Angular `VALID`.
5. Clicar em `Salvar`.

## Comportamento Esperado

O cliente deve ser criado e o formulário deve entrar em modo somente leitura com uma confirmação de sucesso. Se o backend rejeitar os dados, a interface deve exibir o motivo retornado pela API.

## Comportamento Atual

A requisição para clientes recebeu HTTP 422 após 527,5 ms. O formulário continuou preenchido e editável; `errorMessage()` e `successMessage()` permaneceram nulos e nenhum modal/alerta foi exibido.

## Contexto Técnico

- **Ambiente:** local
- **Browser:** Chromium via Puppeteer
- **Backend:** versão/commit não verificado durante a sessão
- **Frontend:** versão/commit não verificado durante a sessão
- **Banco:** PostgreSQL local; consulta MCP não disponível nesta sessão
- **Java:** 21
- **Spring Boot:** 3.4.1

## Impacto

Impede o cadastro de novos clientes e não oferece feedback acionável para o operador. Como clientes são pré-requisito para locações e vendas, o fluxo operacional fica bloqueado.

## Workaround

Não identificado. É necessário inspecionar o payload e a resposta detalhada do 422 no backend; a interface também deve tratar respostas 422 e exibir seus detalhes.

## Status da Correção

**CORRIGIDO em 2026-07-19**. O reteste com CNPJ válido e endereço completo retornou `201`, exibiu confirmação e carregou o cliente salvo. A ocorrência original não foi reproduzida no `HEAD` atual.
